# Implemented architecture

The application is a native WPF/.NET 10 Windows x64 modular monolith. `Mosaic.Core` owns all decimal physical geometry, portrait/landscape comparison and image placement. `Mosaic.Imaging` retains immutable sources, normalizes images and runs isolated offline enhancement workers. `Mosaic.Output` writes precise PDFs and Windows XPS print jobs from the same immutable snapshot. `Mosaic.Storage` owns portable ZIP projects and local preferences. `Mosaic.App` provides the bilingual editor and coordinates jobs.

## Decisions against the architecture recommendation

| Area | Implemented choice and evidence |
|---|---|
| UI | Bespoke WPF XAML tokens and native controls; no WPF-UI or MVVM toolkit dependency. The single small editor coordinates explicit immutable state and async services. This reduces dependency and deployment surface while retaining WPF accessibility, keyboard controls, responsive background processing and readable styles. The actual EN/PL views are rendered by integrated dispatcher checks. |
| Physical units | Exact `decimal` inches rather than decimal mm. Inches are the binding user unit; 8.5/11 paper dimensions and the 72-point/96-DIP output conversion are exact. There is no conversion or page-count rounding back into artwork size. Source aspect ratios govern every adapter, including downsampled previews. |
| PDF | PDFsharp 6.2.4 with one lossless source XObject reused and clipped across pages, conventional Lanczos preprocessing and explicit interpolation. Independent PdfPig checks and XPS serialization establish software dimensions and translations; memory stays independent of the physical poster raster size. Grayscale is opt-in for PDF. |
| AI | Official NCNN Vulkan CUNet worker plus a small isolated NCNN CPU adapter. The advertised upstream CPU mode actually crashed here; the tested CPU adapter uses the same model and padded inference tiles. Full rationale, limits, licenses and measured GPU/CPU results are in [AI.md](AI.md). |
| Logging | A small bounded local diagnostic log replaces Serilog. Five retained daily files and a 1 MiB daily bound cover job stages, exception types/HRESULTs, storage codes and exception stacks. I/O exception messages containing artwork/output paths are omitted; stacks can identify compiled source locations. Logs contain no image data. |
| Projects | Atomic, streamed ZIP source/manifest/thumbnail with checksum/size/schema validation. The store exposes lazy metadata, while editing awaits a bounded full-resolution import. Derived AI images are regenerated rather than duplicated in portable projects. |
| Localization | Paired English/Polish dictionary resources replace `.resx`; one resource update changes controls immediately. String-backed measurements accept partial typing and selected-culture decimals. Actual text edits, rather than focus changes, govern committing; rounded complementary displays cannot alter exact dimensions. |
| Packaging | Pinned .NET10.0.13 self-contained untrimmed/non-AOT folder, Inno Setup7.1 per-user installer, bundled runtime/model licenses and native dependencies. Signing and clean-machine acceptance remain explicit release boundaries. |

## Correctness and failure behavior

The editor uses the last valid geometry while a dimension is being edited. A pending invalid dimension disables output and cannot be erased by a valid margin edit or bypassed with keyboard printing. Dimension, lock, margin, orientation, profile and rotation changes validate the complete candidate layout before committing state; invalid results retain the prior state/layout and show inline validation, including combinations exceeding the sheet limit. Rejected proportion changes retain lock and history. Output snapshots reject inconsistent state/layout pairs. All tiles are row-major disjoint rectangles; partial edge pages retain blank outer paper for trimming. Preview grid labels never enter borderless output.

Project-menu Undo/Redo and keyboard shortcuts retain up to fifty editing snapshots without duplicating source imagery. Original/enhanced comparison opens an independent detail view; canceling a quality-preview change retains the previous recipe and bitmap. Export completion retains its output snapshot when the interface language changes. All application windows fit within the current Windows work area.

Image decode, resampling, PDF generation, project I/O and inference run asynchronously with cancellation and explicit limits. Workers run directly from trusted pinned paths with no shell or network. A canceled project open commits no partial state. AI failure keeps Standard available. Export and project writes replace destinations only after successful completion. One print submission is allowed at a time; native driver settings are validated without recalculating geometry, and scale-to-fit tickets are rejected. Calibration is tied to the exact printer, driver, orientation, pathway and validated ticket fingerprint; nominal PDFs are never compensated silently.

Recovery stores a self-contained project per editor session at most once per editing revision/interval. Exclusive sidecar leases protect live sessions and claim interrupted snapshots, including the legacy recovery file. Restore uses the same dirty-document save/discard/cancel decision as other replacements. A deferred snapshot survives unrelated work and empty close. A restored prior snapshot is retained until a successful new checkpoint or explicit document resolution. Removal, replacement, durable Save and Close drain the writer before resolving obsolete owned/restored recovery and releasing source ownership. Close always leaves WPF's Closing event before retrying, coalesces repeated requests, cancels/awaits any document job, then obtains the unsaved-change decision. Cancel or failure leaves ownership live; only actual Closed disposes resources. Recovery-cleanup failure is actionable and permits retry. See [the lifecycle root cause and regressions](LIFECYCLE_REGRESSION.md). No single-instance restriction or forwarding service is needed. Settings and logs stay under `%LocalAppData%/MosaicTemplateStudio`. No automatic updater or telemetry is implemented.

## Editor presentation

The empty state offers one prominent Open image action and recent projects without disabled configuration placeholders. Import reveals the settings rail; source details and rotation stay with the artwork. Short localized inch labels and an explanation of the automatically adjusted dimension clarify the existing proportion-lock behavior. The rail fits the default window and scrolls at compact sizes. A single Standard/Enhanced selector runs the existing enhancement pathway; CPU fallback sits under Enhancement options.

Remove image sits beside Rotate and returns to the import view. It reuses the existing dirty-document Save/Discard/Cancel choice; clean saved artwork needs no confirmation. Removal blocks new jobs/checkpoints, awaits any active recovery writer, resolves only the current document's owned/restored recovery, then releases its image lease and clears preview, output, validation and document history. Unrelated deferred recovery, language, calibration and printer/paper configuration survive. A subsequent import keeps the printer choices while starting fresh artwork history. The welcome line is craft-focused in English and Polish; offline/privacy information remains in About.

The preview shows complete warm off-white sheets around the exact finished rectangle. Each sheet is translated into artwork coordinates by subtracting its existing `PaperBounds` origin from its `ArtworkBounds` origin, with the resolved physical page width/height. Fit includes the union of those sheets. Discarded margin strips overlap in assembled coordinates; they never introduce extra image coverage or gaps. Faint sheet edges, the finished trim edge and page labels are preview aids, explained beneath the artwork. Grid visibility still controls artwork seam lines and numbering. The core layout and both output adapters are unchanged.

Print and Export PDF share the same persistent visual weight and a target-size, sheet-count and paper summary. First-run calibration guidance appears beside output with Later available; the ruler warning and calibration action remain accessible after dismissal. Progress replaces the footer in place without resizing the artwork; indeterminate animation follows Windows' client-area animation preference. Completion keeps its title and actions outside scrolling instructions, manages keyboard focus, and supports Escape. Native WPF control classes retain their automation peers, with shared rounded templates and explicit hover, pressed, focus and disabled states. No dependencies, processing engines or layout contracts changed; there is no new architectural departure.

Completion sizes to its contents, separates filename, output details and instructions, and groups Open PDF, Show in folder and Back to editing in one wrapping action row. Long filenames use ellipsis with the full name available in a tooltip. Tab/Shift-Tab stay within the completion actions and dismissal restores editor focus. Default PDF filenames retain exact decimal dimensions. The footer and completion use the same compact dimension formatting, marking values rounded beyond four decimal places with `≈`; their tooltips expose the exact model dimensions. File-size formatting follows the selected language explicitly.

## Verification limits

The five focused executable test harnesses check pure geometry, malformed ZIP/image recovery, exact PDF/XPS sizes and translations, real GPU and CPU inference and actual WPF editor operation paths. The UI refinement run adds live in-process automation-peer, focus-traversal and layout checks. EN/PL views at 96/120/144 output DPI are software renders; the host remained at 96 DPI, so this is not actual Windows scaling or independent usability validation. The native Computer Use helper failed at kernel startup with `helper_unknown_error: setup refresh had errors`, including after reset; no native mouse/keyboard-input claim follows from the in-process checks. Physical Epson/Canon output, target-PC hardware, mother-sourced artwork fidelity, fluent Polish wording and clean offline Windows installation remain as recorded in [ACCEPTANCE.md](ACCEPTANCE.md).

The installed executable supports `--verify-install <report-directory>` for the distribution check. It opens the real editor with isolated local data, runs the same import/sizing/AI/comparison/export/project/recovery checks using bundled dependencies and writes `installed-runtime.json` before exiting. This provides an installed-host runtime journey without development tools; it does not pretend to be a separate clean offline machine.
