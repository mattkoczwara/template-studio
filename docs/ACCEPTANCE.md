# First-release requirement and acceptance record

This is an implementation-to-requirement map for [the binding product definition](POSTER_STUDIO_PRODUCT_DEFINITION.md), not a replacement specification. **Software implementation and local checks do not establish production acceptance on the artist's printer or computer.** In particular, the mandatory physical Epson assembly test, clean offline Windows installation and independent target-user task completion remain separate acceptance gates.

Evidence labels below:

- **Implemented** means the connected source pathway exists; it is not a claim that every external device or usability check passed.
- **Software checked** refers to an actually executed automated or rendered check identified in the evidence record.
- **External validation pending** identifies measurements or human review that cannot be inferred from software output.

The coordinated release run must retain its console logs and package manifests under `artifacts/verification/`; installation smoke evidence is under `artifacts/installer-checks/`. An unsigned installer or a development-host install is not described as a signed, clean-machine release.

## Honest release boundary

The app can be implemented and its software pathways checked without a ruler, the artist or a fresh Windows computer. That is not the same as satisfying all physical and human acceptance criteria. A final report must explicitly retain the following pending items until actual evidence exists: Epson direct/PDF-viewer ruler and seam measurements; Canon hardware behavior; the artist's GPU and representative artwork fidelity; clean offline Windows installation; fluent Polish review; Windows display-scaling checks; and independent target-user completion. Code signing requires a real signing certificate and has not been fabricated.
