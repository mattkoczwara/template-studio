# Offline image processing and enhancement

The application uses Magick.NET Q8 x64 15.0.0 for JPEG, PNG, WebP and BMP import. It retains a byte-for-byte original in its local cache, honors EXIF orientation, converts an embedded ICC profile to sRGB, flattens transparency over white, and creates a separate lossless normalized image. The original is embedded when saving a project. No import or processing operation writes the downloaded file.

Standard enlargement uses Lanczos interpolation, producing a reusable asset up to 2× the source, capped at 32 million pixels and an 8,192-pixel edge. A 60-inch artwork never causes allocation of a full-resolution poster-sized image merely because its physical size changes. The geometry engine determines image placement independently of pixel resolution. Preview bitmaps are generated on a background thread, limited to 1,800 pixels by default, loaded completely and frozen before crossing to WPF.

## Bundled AI choice

The selected optional enhancement is CUNet 2× with denoising disabled, preserving illustration contours more conservatively than an aggressive detail/denoise preset. The official `waifu2x-ncnn-vulkan` Windows release **20250915** supplies the NVIDIA/AMD/Intel Vulkan GPU path and the `models-cunet/scale2.0x_model` weights. It runs once on the coherent source image, before paper slicing. It does not infer separately on printer pages. No CUDA, Python, account, external service or runtime model download is required.

The orchestrator verifies compiled SHA-256 pins for both workers, model files and application-local runtime DLLs before use. It starts a fully qualified executable directly with `ProcessStartInfo.ArgumentList`, an installation-owned working directory, redirected output and no shell. GPU inference uses one processing queue and 128-pixel inference tiles, retrying 64 pixels before CPU fallback. Processing reports progress, times out, and cancellation terminates the entire worker process tree. Incomplete output is removed; Standard remains available.

**Measured architecture departure:** The official worker's advertised CPU `-g -1` path crashed with Windows access violation `-1073741819` on both 20250915 and 20220419 in this environment, with CUNet and the alternative upconv model. Shipping that path as a working fallback would be incorrect. A small isolated `mosaic-cunet-cpu.exe` is therefore included. Its source is `vendor/ai/cpu-src/mosaic-cunet-cpu.cpp`; it links official NCNN **20261020**, disables Vulkan and half-precision execution, and uses the same CUNet weights. It follows the upstream eighteen-source-pixel context rule, handles odd final tile dimensions, streams RGB output rows to disk, and does not allocate the complete enlarged output in native memory. This is an output backend addition, not a second print geometry engine.

AI sources are limited to 16 million pixels and a 15,000-pixel edge (the 2× result is at most 64 million pixels). Already large sources remain usable with Standard; an explicit error explains the AI processing limit rather than resizing or changing the physical artwork silently. Source decode permits up to 80 million pixels / 128 MiB input. Native decode limits are 256 MiB memory, 2 GiB disk pixel cache, 30,000-pixel edges, at most four processing threads and a 180-second native operation limit. The process-local ImageMagick map limit is 256 MiB because Magick.NET 15 does not expose `Map`.

Persistent working cache is capped at 4 GiB across imports, Standard/rotated/comparison images, AI output, checksums and staged native-worker files. A root-level file lease serializes allocation admission and publication across services/processes. Conservative write headroom is four bytes per PNG pixel plus 1 MiB, or 64 bytes per source pixel plus 2 MiB for AI/raw staging; new operations can therefore be refused before stored bytes reach the cap. Verified reusable assets bypass new-allocation admission. Original cache assets are never automatically evicted. `PreserveSourceAsync(hash)` shared leases retain every asset of open documents across windows; explicit `ClearCacheAsync(currentSourceHash)` skips all leased sources. Disposable unleased output variants can be removed by `CleanDerivedCache`; source/normalized/preview/AI assets remain. Persistent zero-byte source-lock sidecars preserve cross-process lock identity. Cache capacity, low-disk errors and cancellation preserve current work and use localized storage guidance.

## Actual validation

`dotnet run --project tests/Mosaic.Imaging.Checks -c Release` exercises all four formats, immutable source hashes, white alpha flattening, 90-degree/frozen preview, conventional Lanczos enlargement, actual GPU and CPU inference, dimension checks, cancellation and corrupted input recovery. Output and measured timings are in `artifacts/ai-smoke/result.json`. On this machine the actual NVIDIA device is **GeForce RTX 3070, 8 GiB, driver 617.42**. A synthetic 320×240 illustration crossed inference tile boundaries; both paths produced 640×480 output. One fresh run measured GPU 1.39 seconds and CPU 1.17 seconds, with GPU/CPU normalized RMSE 0.0031 and process peak working set about 62 MiB (this figure excludes native child-process memory). These small-fixture timings are not large-image throughput promises.

The hardened integration pass also checks an actual EXIF orientation tag, Adobe RGB → sRGB color conversion (test pixel `(200,100,50)` becomes `(227,100,42)`), white transparent pixels, corrupt normalized/preview/Standard cache regeneration, rejection of a modified immutable-source hash, and rejection of tampered model weights before execution. Derived images now carry SHA-256 sidecars; cache reuse validates the bytes rather than trusting a filename and pixel dimensions. A PNG encoder may represent standard sRGB with its sRGB/gamma chunks instead of a redundant ICC blob. A real CPU inference was cancelled after its first completed tile; the measured time from cancellation to task termination was **32 ms**, with incomplete raw/PNG working files discarded.

`dotnet run --project tests/Mosaic.Imaging.Checks -c Release -- --large` adds a fresh **1.08-megapixel** vector-style botanical illustration (1,200 × 900) and actually runs both backends to **2,400 × 1,800** pixels. The October 21 integrated pass succeeded: GPU **1.36 s**, CPU **11.58 s**, sampled child peak host memory **167.7 MB** and **117.5 MB** respectively. GPU/CPU normalized RMSE was **0.00196**; strips centered on internal inference boundaries had RMSE **0.00179**, so this fixture showed no excess discrepancy at tile boundaries. These measurements concern synthetic artwork and do not substitute for the target artist's fidelity review.

That same enhanced asset exported at **60 × 45 inches** to **36 landscape Letter pages** in **0.48 s**, producing a **1,006,347-byte PDF**. An independent PdfPig inspection confirmed all 36 MediaBoxes are exactly **792 × 612 points** (`artifacts/ai-smoke/large-pdf-independent.json`). The test host peaked at **142.9 MB**; the large-test working folder contained **3.49 MB** after completion (the retained source cache is separate). Exact measurements and generated PDF path are in `artifacts/ai-smoke/large-result.json`. The export uses the existing shared layout/output adapter, not an image-module tiling implementation.

Live native-process sampling additionally measured about 155 MB GPU-worker host memory and 114 MB CPU-worker host memory for the fixture; this is host working set, not a VRAM measurement. `LastBackend` and `LastWorkerPeakBytes` expose the completed backend diagnostics. GPU driver/device enumeration is performed by the native Vulkan runtime, with CPU fallback after initialization/inference failure.

The actual enhanced image and a Standard comparison were visually inspected: preserved flat color regions, continuous line crossings, smooth curves and no visible grid seam. CPU tile sizes 64 and 128 were also compared (normalized RMSE 0.0029); their exaggerated difference image contained fine contour/rounding changes rather than a visible rectangular tile discontinuity. This is bounded synthetic evidence. No mother-sourced illustration corpus was provided, no target-PC quality review has occurred, and this does not prove that inferred details always match the artist's intent.
