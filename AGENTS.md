AGENTS.md — Mosaic Template Studio
Mission and source of truth
Build a beautiful, dependable, fully offline Windows application that lets a nontechnical artist enlarge downloaded illustrations to exact dimensions in inches, then print or export accurately tiled, full-color mosaic templates. Prioritize physical accuracy, image fidelity, clarity, and a reassuring user experience over feature count.

Product invariants
- Default to the source artwork's full color and original proportions; support proportional and exact width/height entry in inches, with simple optional fit/crop/stretch controls.
- Treat finished physical size as authoritative. Derive all page slices from one deterministic layout model; preview, PDF, and direct print must agree on geometry. Never introduce implicit fit-to-page scaling or duplicated overlap in the default join mode.
- Default to borderless US Letter and butt-joined pages for the Epson EcoTank ET-8500, with optional margins and a margin-aware Canon MF210 fallback. Keep nominal PDF geometry separate from measured printer-specific corrections; never claim unmeasured physical precision or seam continuity.
- In Auto orientation, choose the paper orientation requiring the fewest sheets, preferring portrait on a tie. Permit manual override.
- Provide conventional high-quality enlargement and optional bundled, offline, locally executed AI enhancement, with original-image preservation and an understandable comparison. Handle NVIDIA acceleration, failure, cancellation, and large artworks without locking up the UI.
- Make Print and Export PDF equally accessible. Support self-contained editable projects, English/Polish localization, and common ~24-inch as well as occasional 60-inch templates.
- The interface must be light, airy, refined, legible, and quietly encouraging: show obvious progression and satisfying feedback without a forced wizard, clutter, distracting animation, or loss of user control.
Working approach
1. Inspect the relevant code, tests, and task-specific requirements before editing. Follow existing sound patterns; avoid rebuilds, speculative abstractions, duplicate layout engines, and unnecessary dependencies.
2. For substantial work, make a concise dependency-aware plan, then implement the requested outcome end to end. Resolve routine technical choices independently. If available, delegate genuinely independent tasks in parallel with clear file ownership and integration responsibility; do not parallelize coupled geometry/output changes blindly.
3. Keep image decoding, enhancement, and PDF generation off the UI thread; bound memory and temporary storage, ensure cancellation and recovery, and protect immutable source imagery. Use a shared physical-space layout contract across processing and output adapters.
4. Prefer small, maintainable modules with explicit contracts and minimal coupling. When selecting or changing libraries, evaluate compatibility, redistribution/offline licensing, deployment complexity, performance, and quality with targeted evidence rather than novelty.
5. Keep affected docs synchronized with actual implementation and record meaningful architectural deviations. Do not rewrite product requirements to rationalize incomplete functionality.
Verification and completion
- Test according to risk and changed behavior: geometry/orientation and seam invariants, physical PDF dimensions, print pathways, AI quality/tile boundaries, project recovery, localization, and clean offline installation as applicable. Run focused tests after cohesive changes; broaden testing for integration/release work or when failures justify it. Avoid repeated full-suite or performance runs after every minor edit.
- Treat printer behavior as an empirical boundary: compare Epson ET-8500 direct print and 100%-scale PDF output using a physical calibration pattern. If borderless driver expansion/crop prevents true butt-joins, provide a validated margin-and-trim alternative rather than assuming a software scale factor fixes it.
- Verify meaningful user journeys in both English and Polish, including decimal-comma input, readable UI at Windows display scaling, save/reopen after the original download is removed, and a representative large template.
- Finish by reporting what changed, tests actually run and their outcomes, deviations from the architecture recommendation, and any unverified hardware-dependent limitations. Do not report proposed work as implemented or simulated print results as physical measurements.
